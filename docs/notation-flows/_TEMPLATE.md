# 族手册模板（照这个写，字段顺序不许变）

> 本文件是格式规格，不是交付物。每族一份 `docs/notation-flows/<族名>/README.md`，
> 必须严格按下面两段结构：**族头** + **逐记号细目**。样例见
> `docs/notation-flows/SeqBasic/README.md` 里的 `empty` / `pps` / `pps4` 三条。

## 一、族头（每族必写，四行）

```markdown
# <族名>（<n> 个 id：<id1>…<idn>）

**一句话导读**：这族在算什么（一句） + 与其他族的关系（一句） + 对应
`docs/diagrams/04-kernel-flow/` 的哪条内核链（写出链条名，如「矩阵系」）。

## 共用骨架

按顺序列出该族**所有 id 共用的**步骤（1..k），每步用真实函数名。同族多版本时，
在这里说明「骨架到第 k 步为止一致，之后按 §分叉 各走各的」。
```

## 二、逐记号细目（每个 id 一节，顺序按 id 在 `Registry.idOrder` 里的先后）

字段顺序固定为下面 7 项，缺项写「无」，不要删字段：

```markdown
### `<id>` · <显示名>

- **族 / 模块**：<族名> · `<src/OmegaY/.../X.hs>` · <Caps 类型：文本型 TextCaps / 参数化 ParamCaps(min–max，默认 d) / 序列型 SeqCaps>，后缀 `<suffix，空写 ""`
- **入口**：`<Module.func>`（`X.hs:<行>`），由 `expandNotation` 的 <分支名> 分支调用
- **输入 → 输出**：<输入文本形态> + `--term`（+ `--param`） → <输出文本形态>
- **term / param 语义**：<term 在这条实现里到底是什么量；param 的区间与作用；不适用的写「不参与」>
- **步骤**：
  1. <真实函数名>：<做什么>（`X.hs:<行>`）
  2. …
- **分叉**：<与 §共用骨架 相比，哪些步共用、从第几步开始分叉、分叉判据是什么>
- **错误**：<`条件` → `逐字文本`（`文件:行`）>；无自有错误时写「仅 §00 通用三分支」
```

## 三、硬性规则

1. **不许出现源码里没有的函数名**。每写一个函数名，先 `Grep` 确认它在 `src/` 里存在；
   每个行号都要对得上（`X.hs:行` 打开就该看到那个定义或调用）。
2. **步骤要能复现**：按实现真实执行顺序写，不按「理论上应该」写；分支写成
   「判据 → 走哪支」，不要写「可能…也许…」。
3. **抽象层必须落地**。若要用「取坏序列」「求前驱」这类概括词，必须紧跟括号写出真实函数名。
4. **错误文本逐字照抄**，包括全角/半角与换行（`\n` 写成「（换行）」或直接保留，不要改写标点）。
5. **同族共用骨架的 id**，§步骤 只写它自己真正跑的那几步，把重复部分留给 §共用骨架，
   并在 §分叉 说明它是「骨架 + 参数差异」还是「骨架 + 独立分支」。
6. **不得超过该 id 实际行为**：不补源码没有的特例、不替源码「修正」看起来奇怪的判定。
7. 表格里出现的代码路径一律写成仓库相对路径 `src/OmegaY/...`（不带 `D:\` 前缀）。
